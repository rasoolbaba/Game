# 03 — معماریِ حافظه / Memory Architecture 🧠

**نسخه / Version:** 1.0.0 · **تابعِ:** [`00-INTEGRITY-PROTOCOL.md`](00-INTEGRITY-PROTOCOL.md) (مادهٔ ۶)

> همهٔ حافظه‌ها **فقط-افزودنی (append-only)**، نسخه‌شده در گیت، و **بازتولیدپذیر** هستند. تاریخ بازنویسی نمی‌شود؛ تصحیح = ورودیِ جدید با ارجاع به ورودیِ قبلی.

---

## ۱. پنج لایهٔ حافظه / The five memory layers

| لایه | چه‌کسی صاحبِ آن است | مسیر | محتوا |
|---|---|---|---|
| **فردی / Individual** | هر ایجنت | `memory/teams/<team>/members/<agent>.md` | یادداشت‌ها، فرضیه‌ها، درس‌های شخصیِ همان ایجنت |
| **تیمی / Team** | هر گروهِ دونفره | `memory/teams/<team>/TEAM-LOG.md` | تصمیم‌ها و یافته‌های درون‌گروهی |
| **شورا / Council** | رهبر + همهٔ گروه‌ها | `memory/council/COUNCIL-LOG.md` | تصمیم‌های میان‌گروهی (مبنای تصمیمِ رهبر) |
| **رهبر / Conductor** | رهبر ارکستر | `memory/orchestrator/LEAD-LOG.md` | جهت‌گیری، اولویت‌ها، تصمیم‌های نهایی |
| **ممیز / Auditor** | ممیزِ نگهبان (مستقل) | `memory/auditor/AUDIT-LOG.md` | ممیزی‌ها و پرچم‌قرمزها — کسی بازنویسی‌اش نمی‌کند |

> «حافظهٔ گروهی» در گفتهٔ شما = **لایهٔ شورا**: تصمیمِ رهبر بر مبنای تصمیم‌سازیِ تیم‌ها.

## ۳. قالبِ استانداردِ ورودی / Standard entry format

هر ورودی، صرف‌نظر از لایه، این شِما را دارد (Markdown سبک، قابلِ خواندنِ انسان و ماشین):

```
### MEM-<lang|team>-<شماره> — <YYYY-MM-DD> — <عنوانِ کوتاه>
- نوع / Type: تصمیم | یافته | فرضیه | درس | سؤالِ باز
- زمینه / Context: <چرا این موضوع مطرح شد>
- محتوا / Body: <…>
- شواهد / Evidence: <لینک/فرمان/diff/اسکرین یا «—»>
- برچسبِ حقیقت / Truth-tag: VERIFIED ✅ | ASSUMED ⚠️ | UNKNOWN ❓
- ارجاع‌ها / Links: <ADR-… , INV-… , EXP-… , MEM-…>
```

---

## ۴. قواعد / Rules
1. **فقط-افزودنی:** هرگز ورودیِ قبلی را پاک/ویرایش نکن؛ ورودیِ تصحیحی بنویس و به قبلی لینک بده.
2. **به‌روزرسانیِ پایانِ کار:** در پایانِ هر کارِ معنادار، لایه‌های مرتبط را به‌روز کن (الزامِ مادهٔ ۶).
3. **ارجاعِ متقابل:** حافظه‌ها به دفترها (`INVENTIONS`/`EXPERIENCES`) و ADRها لینک می‌دهند تا یک «گرافِ دانش» شکل گیرد.
4. **scratchِ موقت** زیر `memory/**/_scratch/` نوشته می‌شود و در گیت نمی‌آید (`.gitignore`).
5. **حقیقتِ سه‌حالتی** در هر ورودی الزامی است (مادهٔ ۱).

---

## ۵. چرا Markdown و نه دیتابیس؟ / Why Markdown, not a DB? (فعلاً)
- `VERIFIED` بودنِ خودِ حافظه: گیت = منبعِ حقیقتِ بازتولیدپذیر و قابلِ‌بازبینی توسطِ انسان و ممیز.
- بدونِ وابستگیِ زودهنگام؛ مطابقِ «ابزار در برابر هسته» (مادهٔ ۳-۳).
- اگر در آینده مقیاس لازم شد، مهاجرت به یک سامانهٔ ساخت‌یافته از طریق ADR انجام می‌شود (`ASSUMED ⚠️`: نیاز به بازبینی در مقیاس بالا).
